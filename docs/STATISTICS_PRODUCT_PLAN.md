# 统计学学习与游戏化产品总规划

> 版本：0.1（规划稿）  
> 适用项目：`family-statistics-learning` / 小小统计学  
> 原则：先用生活问题建立直觉，再用图表和可重复实验验证，最后再引入公式与代码。

## 1. 对现有工作区的判断

当前项目已经有一个适合继续扩展的纯静态原型：

- [`index.html`](../index.html)：完整的“故事 → 概念 → 实验 → 带回家的思考”单课壳层，已有平均数饮水案例。
- [`src/lessons.js`](../src/lessons.js)：课程注册表，已预留中位数、波动、概率。
- [`src/app.js`](../src/app.js)：本地计算、滑杆实验、恢复默认、主题和打印。
- [`src/styles.css`](../src/styles.css)：共享视觉令牌（后续课程应复用，不要为每课另造视觉系统）。
- [`docs/DEVELOPMENT_GUIDE.md`](DEVELOPMENT_GUIDE.md)：明确了离线、可访问、可打印、演示数据标注和插件化内容协议。
- [`docs/LEARNING_ROADMAP.md`](LEARNING_ROADMAP.md)：已经从平均数排到中位数、众数、波动、概率、抽样偏差、相关与因果。

因此建议保留 HTML 平白、正式、可打印的展示层；游戏层作为同一知识内容之上的“挑战模式”，而不是把正式课程改成炫技游戏。

## 2. 教材参考与总体教学主线

参考 OpenIntro Statistics 的描述统计—概率—推断主线、Berkeley Data 8 的“推断思维 + 计算思维 + 真实问题”三线融合、以及 Allen Downey《Think Stats》以可运行数据分析贯穿章节的做法，建议形成 8 个阶段：

| 阶段 | 核心问题 | 关键知识 | 首批生活案例 | 应交付的交互 |
|---|---|---|---|---|
| 0. 数据思维 | 什么算数据？ | 个体、变量、观测、总体/样本、测量尺度 | 家庭饮水、通勤时间 | 给数据贴标签、识别变量类型 |
| 1. 典型值 | 一句话怎样描述一群人？ | 平均数、中位数、众数、加权平均 | 水杯数、考试分数、房价 | 拖动极端值，比较三种中心 |
| 2. 分布与波动 | 平均一样，为什么体验不同？ | 极差、四分位距、方差、标准差、箱线图、z 分数 | 两个班成绩、候车时间 | 合并/拆分数据，观察分布和离散 |
| 3. 可视化与叙事 | 图表会不会骗人？ | 条形图、直方图、散点图、分组、轴尺度、缺失值 | 手机使用、家庭预算、天气 | 修复误导图表并解释改变了什么 |
| 4. 概率与模拟 | “可能”如何量化？ | 样本空间、条件概率、独立性、期望、模拟 | 抽签、骰子、生日问题、排队 | 预测—运行 100/1000 次—比较理论概率 |
| 5. 抽样与不确定性 | 从少量人能否了解整体？ | 随机抽样、抽样分布、标准误、置信区间 | 民调、产品满意度、抽检 | 反复抽样看区间覆盖率 |
| 6. 检验与决策 | 观察到的差异是否超出随机波动？ | 零假设、p 值、效应量、功效、多重比较 | 新教学法、A/B 按钮点击 | 先下注结论，再看模拟 null distribution |
| 7. 关系与预测 | 一起变化是否代表因果？ | 相关、回归、混杂、因果图、实验/观察研究 | 冰淇淋销量与溺水、睡眠与成绩 | 拖动混杂变量，识别“第三变量” |
| 8. 负责任的数据科学 | 结果能否被信任和复现？ | 偏差、公平、隐私、可复现、数据来源 | 人脸/推荐/公共卫生数据 | 给研究报告做审稿，标出证据缺口 |

### 推荐教材搭配

- **直觉入门**：OpenIntro Statistics：章节结构适合做概念地图和练习题；其开放教材入口可参考 [AIM Open Textbooks](https://textbooks.aimath.org/textbooks/approved-textbooks/diez-barr-cetinkaya-rundel/)。
- **计算与真实数据**：Berkeley [Data 8](https://data8.org/)：课程明确结合推断、计算和现实相关性，提供公开教材、Notebook、数据集和历年课程材料。
- **代码化统计思维**：Allen Downey 的 [Think Stats](https://allendowney.github.io/ThinkStats/index.html)：适合把每个知识点转成可执行模拟。
- **统计学习扩展**：[ISLR/ISLP](https://www.statlearning.com/) 适合在基础统计后进入回归、分类、重抽样、正则化、树模型和无监督学习；它不是基础概率/因果推断教材，应与 OpenIntro 配合。
- **可视化灵感**：Brown 的 [Seeing Theory](https://seeing-theory.brown.edu/) 曾以交互方式展示概率和推断；项目已归档，当前旧站点需注意可用性变化，不应把它当作本项目的运行依赖。

## 3. “更多例子”内容生产法

每个知识点至少准备 6 类例子，避免只换数字：

1. **家庭例**：饮水、睡眠、购物、零花钱；低门槛，负责建立直觉。
2. **校园/工作例**：考试、通勤、会议时长；负责连接真实决策。
3. **自然与游戏例**：骰子、硬币、抽卡、生日；适合模拟和挑战。
4. **公共议题例**：民调、天气、医疗筛查；强调不确定性和基率。
5. **反例**：离群值、辛普森悖论、相关不等于因果；专门纠正常见误解。
6. **开放数据例**：城市空气、交通、体育、电影；用于课程后半段和 GitHub 贡献。

每个案例采用统一卡片：

```text
问题（先猜） → 数据（注明来源/是否演示） → 图表 → 可操作变量
→ 理论解释 → 反例/边界 → 一句话结论 → 可复现参数
```

建议首批案例库（可作为 `content/examples.json`）：

- 平均数：饮水 6/4/2/4；加入“某天 20 杯”观察极端值。
- 中位数：四人家庭收入加入一位高收入者；比较平均数与中位数。
- 众数：最常穿鞋码、最常点饮料；讨论众数可能不唯一。
- 波动：两个班平均分相同但一个班更整齐；比较 IQR 与标准差。
- 概率：两枚硬币、生日碰撞、抽卡保底；理论值与模拟频率对照。
- 抽样：从一袋不同颜色糖果抽样估计颜色比例；展示小样本不稳定。
- p 值：一枚“可疑硬币”模拟正面次数；先不贴“作弊”标签。
- 相关/因果：冰淇淋销量与溺水；加入气温作为混杂变量。
- 回归：用房间数预测房租；显示预测误差而不是只显示拟合线。
- 公平与隐私：推荐算法对不同群体的错误率；只用合成数据做教学。

## 4. 游戏化产品方向

### 4.1 推荐定位：Stat Quest / 统计侦探

不是刷题 App，而是“提出主张—寻找数据—进行实验—解释证据”的短局侦探游戏。玩家每局 5–10 分钟，面对一个生活或公共议题，完成：

1. 选择要收集/查看的变量；
2. 预测可能结果并锁定假设；
3. 操作样本、模拟、图表或模型；
4. 对证据强度、偏差和不确定性做判断；
5. 写一句面向普通人的结论。

成功条件不是“算出唯一数字”，而是结论准确、边界诚实、证据与主张匹配。这样能把统计学的核心实践融入玩法。

### 4.2 三种可选玩法

- **侦探调查（推荐 MVP）**：案件卡 + 可视化实验 + 结论审稿；最适合现有 HTML。
- **概率实验室**：玩家经营抽奖/资源系统，必须用期望和风险控制预算；反馈快、易做成小游戏。
- **多人新闻编辑部**：玩家分工采样、分析、审稿；后期再做，涉及账号、同步和社区治理，暂不作为首个 Demo。

### 4.3 进度与奖励

- XP 只奖励“可解释过程”，不奖励盲猜。
- 徽章：能识别离群值、能区分相关/因果、能发现抽样偏差、能报告区间。
- 错误反馈采用“再抽一次样 / 换图表 / 查看反例”，不要只显示红叉。
- 每关保留实验参数和玩家结论，生成可打印的“统计调查报告”。

### 4.4 技术路线

**阶段 A（1–2 周）**：保持纯 HTML/CSS/JS，无框架、离线可运行；新增一个中位数关卡和一个概率模拟关卡。内容 JSON 与实验函数分离。

**阶段 B（2–4 周）**：加入挑战模式、localStorage 进度、种子随机数、结果分享（导出 JSON/打印 HTML）；补单元测试和移动端/键盘检查。

**阶段 C（4–8 周）**：若试玩验证有效，再考虑 Vite/TypeScript、组件化图表、GitHub Pages 自动部署；仍保留无 JS 时可读的正式内容。

**阶段 D（后续）**：多人协作、排行榜、用户提交案例；必须先设计隐私、审核、无障碍和数据授权，不能因“游戏化”牺牲科学严谨性。

## 6. 建议的首个 Demo

**Demo 名称：极端值来袭——平均数、中位数谁更可靠？**

- 场景：四位家庭成员的通勤分钟数 `[20, 25, 30, 35]`，玩家可以加入“老板/远程员工”等角色。
- 目标：先选一个代表“典型通勤”的数；再拖动一个极端值；最后解释为何平均数改变更明显。
- 游戏循环：预测 → 拖动数据 → 比较 mean/median → 选择结论 → 查看反例。
- 结束卡：显示计算过程、数据表、玩家选择、正确解释和“何时不能下结论”。
- 实现：复用当前实验卡和路线卡，不改整体 HTML 壳；新增 `content/median.json` 与一个 `median` 实验函数。
- 验收：离线打开、手机宽度、键盘操作、打印、恢复默认、每次随机可复现；至少 3 名真实用户试玩并记录误解点。

## 7. 12 周执行计划

- **第 1–2 周**：完成数据模型、内容模板、案例标签；把中位数课做成正式 HTML。
- **第 3–4 周**：完成波动和概率各一个可运行实验；建立 `content/examples.json` 初版。
- **第 5–6 周**：做“统计侦探” Demo，加入挑战状态、结论反馈、localStorage。
- **第 7–8 周**：用户试玩；重点观察是否理解“样本/总体、平均数/中位数、概率不是保证”。
- **第 9–10 周**：修正文案和可视化，增加开放数据案例与来源页。
- **第 11–12 周**：整理 README、贡献指南、许可证、GitHub Pages 发布和版本截图。

## 8. 当前决策建议

先选择“侦探调查 + 平均数/中位数 Demo”，而不是直接做多人游戏或复杂 3D。原因是它最大程度复用现有 HTML，能用最少工程验证最重要的教学假设：**更多可操作例子是否真的帮助学习者解释统计结果**。等 Demo 证明玩家能从实验走到可靠结论，再扩展概率、抽样和因果模块。
